# 실행 계획: 양주 무인 반찬가게 「온담찬」 — 로고 → 상세페이지 → 홈페이지(+결제)

## Context
조피디님이 첨부한 「양주시 1인 무인 반찬가게 사업계획서」(2026.08.21)를 바탕으로 브랜드 「온담찬」과 온라인 매장을 만듭니다.
- 필수 결과물: 로고, 상세페이지, 홈페이지(사업소개·상품·상세·결제), 결제 시스템
- 추가 요청: 어르신(실버) 음식 전용 코너 → 「어르신 밥상」
- 진행 방식: `homepage-builder-kr` 스킬(전역 설정·보강 완료) 절차에 따라 **메타프롬프트 → 로고 3안 → 상세 3안 → 홈 3안 → 실제 사이트** 순서로 만듭니다.
- 실사 이미지와 심볼은 GPT 이미지 모델(`gpt-image-2`)을 CLI로 생성합니다.

## 현재 상태 (재확인)
- `OPENAI_API_KEY` 없음, `api.openai.com` 차단 → 환경 설정은 사용자만 변경 가능(Claude가 대신 설정할 수 없음)
- A단계(메타프롬프트·메뉴·로고 프롬프트)는 커밋 1313a73으로 완료 → 키가 들어오면 `brand/generate-logos.sh`로 C단계부터 바로 시작

## 새 세션 시작 절차 (사용자 선택: 새 세션에서 로고 3안 진행)
1. 새 세션에서 `git checkout claude/confident-gates-1vkps4` 상태 확인(최신 a4d38f3), `echo ${OPENAI_API_KEY:+set}` + `curl api.openai.com` 으로 키·네트워크 확인
2. `brand/generate-logos.sh` 실행 → `brand/logo/candidates/logo-{A,B,C}-{1,2}.png` 6장 + `brand/prompts.jsonl`
3. 직접 열어 보고 품질 점검(한글 '온담찬' 철자, 32px 축소·단색 판독) → 깨진 컷은 프롬프트 수정 후 재생성
4. 비교 페이지 Artifact(흰·크림·갈색 배경, 32px, 단색, 용기 라벨 모의) → 사용자 선택 → SVG 재작성
5. 이어서 D(상세 3안) → E(홈 3안) → F(사이트)

## 남은 실행 단계

### 0. 선행 조건 — 조피디님 설정 (GPT 이미지용)
- 클라우드 환경 설정에서 두 가지를 바꿉니다.
  - 환경변수 `OPENAI_API_KEY` 추가
  - Allowed domains에 `api.openai.com`, `js.tosspayments.com`, `api.tosspayments.com`, `log.tosspayments.com` 추가
- 새 세션부터 적용됩니다.
- 설정 전에는 이미지가 필요 없는 A·B와 사이트 골격(F 일부)을 먼저 진행합니다.
- 이미지 자리는 가짜로 채우지 않습니다. "생성 대기" 표시만 둡니다.

### A. 메타프롬프트 3종 → `brand/meta-prompt.md`
1. **브랜드 바이블**
   - 컬러 토큰(대략값, 대비 검증 후 확정):
     - 크림 `--paper` #FBF6EC
     - 된장 갈색 `--brand` #7A4E2D
     - 진한 먹 `--ink` #2B211A
     - 고추 주홍 `--accent` #C8462B (CTA·강조에만)
   - 폰트: Pretendard(본문) + Noto Serif KR 또는 손글씨 1종(제목)
   - 톤과 금지 표현: 고령친화식품·저염·효능 표현 금지 (분석 문서 5장 기준)
2. **GPT 이미지 프롬프트 템플릿**
   - 대상: 로고, 집밥상, 용기 상품컷, 가게 내부
   - 구조: 배경 → 피사체 → 디테일 → 제약
   - 공통 제약: 한국 가정식, 인물 없음, 이미지 속 글자 없음
3. **페이지 빌드 프롬프트**: 섹션별 목적, 카피, 레이아웃
- `brand/menu.json`: 예시 메뉴 15개 + 어르신 밥상 2개
  - 가격·용량·원재료·알레르기 자리(빈칸)·부드러움 단계 포함
  - 이후 시안과 사이트가 같은 데이터를 씁니다.

### B. 레퍼런스 조사 → `brand/refs/refs.md`
- 국내외 반찬·집밥·델리·밀키트 사이트 6~9곳을 고릅니다.
- Playwright로 1440·375px 스크린샷을 찍고 "가져올 점 / 피할 점 / 온담찬 적용" 표로 정리합니다.
- 결과는 Artifact로 공유합니다.

### C. 로고 3안 (스킬 Phase 1.5) — ✅ 확정 2026-10-21
- **결정: C안 원형 엠블럼(기본) + A안 가로형.** 확정 파일·가이드는 `brand/logo/` (`README.md`, `guide.html`)
- OpenAI 키가 없어 SVG 시안으로 먼저 결정. GPT 이미지 후보는 생략 가능(필요하면 키 등록 후 참고용으로 생성)
- `gen-image.mjs`로 생성합니다(`--quality medium`, 안별 2컷).
  - A안: 김 오르는 밥그릇 + 워드마크
  - B안: 두 손이 건네는 그릇 + 워드마크
  - C안: 두 모티브를 합친 원형 스티커 엠블럼
- 비교 페이지(Artifact)에 함께 보여줄 것: 흰·크림·갈색 배경, **32px·단색 축소본**, 용기 라벨 모의
- 선택하시면 SVG로 다시 그려 확정합니다(`brand/logo/`).
  - logo, horizontal, mono, symbol, favicon, OG 1200×630

### D. 상세페이지 3안 — 1인 저녁세트 (Phase 5.5)
- `references/detail-page.md` 구조를 따릅니다. 3안은 톤만 다르게 합니다.
  - 따뜻한 집밥 / 깔끔한 정보형 / 차분한 에디토리얼 — 모두 R4 색 범위 안에서
- 꼭 들어갈 것:
  - 제조시간 라벨 예시를 크게
  - 정보 고시 블록
  - 픽업 안내와 FAQ 4개
  - '연출 이미지' 고지
- 이미지: 세트 구성 탑뷰, 용기 상품컷, 국 클로즈업 (gpt-image-2, 확정 컷만 high)
- 375·860px 스크린샷으로 검증한 뒤 Artifact로 공유하고 선택받습니다.

### E. 홈페이지 3안
- 선택된 상세 틀과 로고로 정적 HTML 시안 3개를 만듭니다(`prototypes/home-A|B|C.html`). 레이아웃 방향만 다르게 합니다.
- 각 시안에 들어갈 화면:
  - 홈: 두 손님 히어로, 오늘의 반찬, 이용 방법 3단계, 제조시간 약속, 매장 안내
  - 사업소개: '만드는 사람' 자리 포함
  - 메뉴 목록
  - 어르신 밥상
  - 결제 화면 모형
- 375·768·1440px 스크린샷으로 검증합니다. 한글 어절 끊김, WCAG AA 대비, 18px 본문을 봅니다.

### F. 실제 사이트 `site/` (선택안 기준)
- feature-planner로 세부 계획을 세우고 승인받습니다.
- 스택: Next.js(App Router) + TS + Tailwind + shadcn/ui
- 결제·DB 코드는 스킬의 `references/payments-toss.md`·`supabase-setup.md` 템플릿을 그대로 재사용합니다.
  - `lib/supabase/admin.ts`
  - `/api/orders` 서버 금액 계산
  - `/api/payments/confirm` 금액 대조
  - `orders`는 anon 접근 차단
- 라우트:
  - `/`, `/about`, `/menu`, `/menu/[slug]`, `/silver`
  - `/checkout`: 픽업 슬롯, 받는 분, 배송 옵션은 스위치로 숨김
  - `/checkout/success|fail`, `/policy/terms`, `/policy/refund`
  - `/admin`: 오늘 메뉴·품절·주문 목록, Supabase Auth 이메일 로그인
- DB 테이블: `products`, `pickup_slots`, `orders`(fulfillment_type, recipient_*, address_* nullable), `order_items`
  - RLS를 켜고, 마이그레이션은 Supabase MCP로 적용합니다. 프로젝트 생성·비용은 사전에 확인받습니다.
- 주문 이메일 알림: Resend 등 메일 서비스 키가 필요합니다. 키가 없으면 관리자 화면 알림만 둡니다.
- 결제는 토스 문서용 공개 테스트 키로 합니다.
- 푸터에 사업자·통신판매업 신고번호 자리를 둡니다.
- Vercel: 프로젝트 'ondamchan'을 GitHub와 연동해 Preview 배포 → Production은 확인 후
