## 3. 시험으로 알게 된 것
- **다시 말하기를 쉼 없이 바로 이어 하면 받아쓰기(Whisper)가 반복을 한 번만 적어** 글 기반 감지로는 못 찾음.
  NG 낱말("다시 할게요" 등)이나 쉼이 끼면 찾음. 소리 기반 반복 감지는 다음 과제.
- 샘플 영상은 표지 슬라이드 1장 + 교수 카메라 원형 창 + 녹화 위젯. 카메라 창의 화면 잡음은 0.1% 수준 → 기준 1%로 충분.
- 받아쓰기 속도(4코어 CPU): medium 은 영상 길이의 1.9배, small 은 0.5배지만 오인식이 많음 → 기본은 medium, GPU 없는 저사양 PC 는 small + 꼼꼼한 검수.
- 번역(en)이 빈 작업에서 ⑥이 멈추던 기존 문제 수정 (내용 있는 언어만 자막 생성).
- 3분50초 샘플 대본 끝의 녹화 중 잡담("왜 PPT를 안 넘겨?… 미치겠다")은 'NG·혼잣말 의심'으로 잡힘 (단위 시험에 포함).

## 3-1. 3분50초 실영상 결과 (2026-11-17)
- 받아쓰기 554초(영상 길이의 2.4배), 나머지 단계 약 1분. 슬라이드 전환 0회 (표지 1장 — 정답과 같음).
- 끝부분 녹화 중 잡담 4구간 → NG 낱말이 없는 짧은 말까지 **한 덩어리 NG 컷 제안**(3:30–3:53, 23초)으로 묶도록 개선.
  묶는 범위: NG 사이에 끼인 짧은 말, NG 뒤 영상 마지막 짧은 말. NG 앞 강의 문장은 묶지 않음.
- 승인 후 3:53 → 3:30, 자막·스크립트에서 잡담 문장 0건.
- 챕터 합치기 개선: 가장 짧은 챕터를 더 짧은 이웃과 합치고 긴 쪽 제목을 남김. 합쳐진 제목 후보는 검수 화면에서 눌러 고를 수 있음.
- 검수 화면이 챕터·퀴즈 근거 시각을 초 단위로 반올림하던 문제 수정 (손대지 않으면 원래 값 유지).
- 한계: 문장 끝을 다음 문장에서 다시 말한 경우(예: "과거의 효과가 더 효과적입니다" → "과거에 효과적이었던…")는
  첫 시도가 오인식돼 글로는 찾기 어려움. 자막 검수에서 고침 (AI 교정 단계가 지움).

## 3-2. 립싱크(입모양-목소리) 보정 (2026-11-17)
- 증상: PIP(교수 카메라 창) 입모양이 목소리보다 늦음.
- 원인: **원본 녹화 자체** — 화면 녹화 프로그램이 웹캠 영상을 마이크 소리보다 약 0.27초 늦게 담음.
  엔진은 싱크를 바꾸지 않음을 확인 (소리 0ms, 영상 1프레임 이내). 말끝 장면에서 소리는 끝났는데 입이 '…니다'를 계속 말함.
- 측정 함정: 1Hz 아래 느린 성분은 '말 전에 숨 들이쉬며 입 벌리기' 때문에 반대 방향(+150ms)을 가리킴 → 음절 리듬 대역(2~7Hz)으로 측정.
- 보정: ② 영상 정리에서 `av_offset_ms: auto` → 소리를 290ms 늦춤. 보정 후 측정 +10~+20ms (세 구간 모두, 자연 범위).
- 함께 고친 숨은 결함: 받아쓰기를 다시 하면 구간이 바뀌는데 예전 AI 결과 파일(llm_text.json)을 쓰면 자막이 밀림
  → ④ 자막 단계에서 글이 맞지 않으면 멈추고 알림.
